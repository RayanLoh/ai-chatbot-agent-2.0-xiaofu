# 后端五项修复（2026-10-17）

1. Google 验证前按网络限流；格式明显错误的 token 不取公钥。公钥使用带互斥刷新的缓存，尊重禁用缓存指令，缓存时间最多 5 分钟，网络超时 5 秒，故障退避 5 秒。无效 token 返回 401；网络或验证服务故障返回 503 / AUTH_SERVICE_UNAVAILABLE，前端保留登录。
2. 恢复历史时，旧公共链接和返回 400/404/409 的历史图片被跳过，文字历史保留。不会从公共链接下载图片，也不会自动认领归属。回复附带 HISTORY_IMAGES_UNAVAILABLE 提示并持久保存；本次新附件失败仍会明确报错。存储服务故障 503 不会被当成图片丢失静默忽略。
3. 游客网络额度、游客总额度、用户方案次数和预算统一在模型调用前原子准入。密钥/价格/存储配置缺失、图片预处理失败、输入过长或预算拒绝时不扣游客次数。进入生成后发生取消/超时等，仍保留已预留额度。用完总额度的 token 不再耗掉其他人的网络额度。
4. 自动创建的新会话推迟到成功提交问答时，与消息和结果在同一数据库事务中创建。失败/取消不产生空会话；用户明确创建的空会话保留。请求编号和失败记录继续保留，防止重复调用。
5. /models 返回 available、unavailable_reason，default_model 只取配置可用模型，没有时为 null。图片模型还要求私有存储配置。前端展示原因并阻止选择/发送不可用模型；后端图片生成也会在调用模型前预检存储。

GET /health 仍是进程存活检查；GET /readiness 是**配置**就绪检查，不会调用真实 Google、Gemini、Supabase 或 R2。它返回 scope=configuration、各项配置状态和模型状态，缺少聊天所需配置时返回 503。该接口不代表已验证外部连通性、账户模型权限、数据库迁移或桶的实际公共访问设置。

部署前备份数据库，先在测试库按顺序应用 migrations/001、002、003、004_backend_reliability.sql。004 更新模型准入函数签名与延迟会话创建；不能只发布 Python 代码。旧请求结果、历史聊天和已持有图片归属保留。

本地验证：后端最终全量 78 项通过；前端全量 39 项通过，生产构建通过。四份迁移及各阶段 SQL 断言在 PGlite 通过，CI 已加入 PostgreSQL 16 的 004 检查。本地无真实凭据的预览后端已恢复，浏览器确认未配置模型显示原因且不可选择。没有使用真实密钥访问外部服务，没有执行生产迁移或推送。订阅保持模板状态。
